# ZipAI 백엔드 병합 안내

- 전달일: 2026-09-09
- 개발 환경: Java 21, Spring Boot 3.5.4, Gradle
- 목적: 송성근 담당 백엔드와 화면 연동 변경을 팀의 최신 프로젝트에 안전하게 병합하기 위한 전달본

## 가장 먼저 확인할 내용

이 폴더는 완성 프로젝트 전체가 아니라 **변경 파일 전달본**입니다. 팀 프로젝트에 폴더 전체를 한 번에 덮어쓰지 말고, 아래 순서대로 Git 브랜치에서 병합해 주세요.

특히 `User.java`, `AuthService.java`, 각 Controller, `application.yml`, `build.gradle`은 다른 작업자의 변경과 충돌할 가능성이 높습니다. 충돌 시 한쪽 코드를 삭제하지 말고 양쪽 기능을 합쳐야 합니다.

실제 비밀번호, OAuth Client Secret, SENS Secret Key, DB 데이터와 로그는 포함하지 않았습니다.

## 폴더 구성

## 포함된 주요 기능

1. 회원 보안
   - 회원가입 및 로그인 보강
   - 이메일/SMS 인증번호 발급·검증 구조
   - 인증번호 만료, 입력 횟수 및 발송 횟수 제한
   - 회원정보 수정, 비밀번호 변경, 회원탈퇴 API
   - 로그인 시도 제한, 계정 잠금, 비밀번호 재설정 기반

2. 소셜 로그인
   - 카카오 OAuth 로그인
   - 구글 OAuth 로그인
   - 소셜 계정과 내부 사용자 계정 연결 정보 저장

3. 관리자 기능
   - 관리자 통계 집계 및 캐시 갱신
   - 관리자 작업 감사 로그
   - 매물·문의·커뮤니티·방문 요청 API 보강

4. 안전진단
   - 등기사항증명서 PDF 검사 및 위험 키워드 분석
   - CLOVA OCR 연동 인터페이스
   - 진단 결과와 원본 파일 저장·조회·다운로드
   - AI 분석 한계와 주의사항 표시

5. 방문 예약
   - 신청, 승인·거절 이후 상태 처리
   - 방문 일정 생명주기와 알림·리마인더 스케줄러

6. 데이터 유지 및 화면 연동
   - 커뮤니티 글 서버 저장
   - 마이페이지의 매물·문의·찜·방문·진단 이력 연결
   - 고객센터 문의 상세 및 관리자 화면 연결

세부 작업 내역과 API 설명은 `docs/README.md`, `docs/백엔드.md`를 참고하세요.

## 권장 병합 순서

1. 팀의 최신 브랜치에서 새 작업 브랜치를 만듭니다.

   ```powershell
   git switch -c feature/merge-songseonggeun-backend
   ```

2. `backend-files/build.gradle`의 의존성을 팀 프로젝트의 `build.gradle`에 합칩니다.
3. `backend-files/src/main/java`의 신규 파일을 동일 경로에 추가합니다.
4. 기존 Java 파일은 비교 도구로 변경된 메서드와 필드만 병합합니다.
5. `application.yml`은 덮어쓰지 말고 신규 설정 항목만 합칩니다.
6. DB 마이그레이션 번호가 팀 프로젝트와 겹치는지 확인한 뒤 추가합니다.
7. 필요한 화면 기능을 사용할 경우 `frontend-integration` 파일을 비교·병합합니다.
8. 테스트와 로컬 실행 검증 후 커밋합니다.

## DB 마이그레이션 주의사항

전달본에는 `V2`부터 `V6`까지 포함되어 있습니다.

```text
V2__account_security_and_admin.sql
V3__verification_consumption_and_defense_reports.sql
V4__defense_report_original_file.sql
V5__visit_reservation_lifecycle.sql
V6__oauth_identities.sql
```

팀 프로젝트에 같은 번호의 Flyway 파일이 있으면 번호를 팀의 마지막 번호 다음으로 변경해야 합니다. 파일 이름만 변경하지 말고 SQL 사이의 적용 순서도 유지하세요. 이미 운영 DB에 적용한 마이그레이션 파일의 내용은 수정하면 안 됩니다.

## 환경변수

`backend-files/.env.example`을 참고하되 실제 값이 포함된 `.env` 파일은 별도로 안전하게 관리하세요.

주요 변수:

- DB: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`
- 이메일: `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`
- SMS/SENS: `SMS_PROVIDER`, `NCP_ACCESS_KEY`, `NCP_SECRET_KEY`, `NCP_SENS_SERVICE_ID`, `NCP_SMS_FROM`
- OCR: `CLOVA_OCR_INVOKE_URL`, `CLOVA_OCR_SECRET`
- OAuth: `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- 보안: `VERIFICATION_PEPPER`, `REPORT_FILE_KEY`

비밀값을 Git에 커밋하지 마세요. `SMS_PROVIDER=disabled`이면 실제 문자는 전송되지 않습니다.

## 병합 후 검증

프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
.\gradlew.bat test
.\gradlew.bat bootRun --no-daemon --args="--spring.profiles.active=local-demo"
```

서버가 실행되면 다음 주소를 확인합니다.

```text
http://127.0.0.1:4173/api/health
http://127.0.0.1:4173/index.html
```

최소 확인 항목:

- 일반 회원가입·로그인
- 카카오/구글 버튼과 OAuth 콜백 설정
- 게시글 작성 후 다른 화면을 다녀와도 유지되는지
- 문의 작성·조회·답변
- 찜 목록과 마이페이지 개수 일치
- 방문 신청·승인·거절·완료 상태
- 관리자 권한이 없는 사용자의 관리자 API 접근 차단
- PDF 안전진단 업로드·과거 결과 조회·원본 다운로드
- 회원정보 수정·비밀번호 변경·회원탈퇴
- 관리자 통계와 감사 로그

## 로컬 시연 도구

`local-demo` 폴더의 파일은 팀 프로젝트 루트의 동일 상대 경로로 배치할 때 사용할 수 있습니다. 운영 배포에는 필요하지 않습니다.

- `ZipAI-Start.bat`: 로컬 데모 서버 시작
- `ZipAI-Stop.bat`: 시작 파일로 실행한 로컬 데모 서버 종료
- `scripts/*.ps1`: 위 BAT 파일이 호출하는 실제 실행 스크립트

## 포함하지 않은 항목

- `.env` 및 실제 API 키
- `.runtime/` PID와 실행 로그
- `build/`, `.gradle/` 빌드 결과
- SQLite/H2/MySQL 실제 데이터와 백업
- Git 저장소 메타데이터
- 원본 프로젝트의 변경되지 않은 파일

## 문제 발생 시 우선 확인할 곳

1. 컴파일 오류: `build.gradle` 의존성 누락 여부
2. 애플리케이션 시작 오류: `application.yml`과 환경변수
3. DB 오류/500 응답: Flyway 마이그레이션 번호 및 적용 여부
4. 버튼 무반응: `frontend-integration/static/js` 병합 여부
5. OAuth 오류: 공급자 콘솔의 Redirect URI와 환경변수
6. SMS/OCR 미동작: 공급자 설정값과 활성화 옵션
