# ZipAI (index.html 중심 설명서)

## 개발 작업 기록

### 2026-08-24 — 네이버 SENS 준비 및 등기사항증명서 PDF 분석

#### 작업 과정

1. 기존 범용 SMS 웹훅 구조를 네이버 클라우드 SENS 전용 서명 방식으로 교체했습니다.
2. 실제 업체 키가 없는 현재 환경에서는 외부 요청을 보내지 않으며, 추후 환경변수만 입력하면 활성화되도록 구성했습니다.
3. PDFBox 기반 등기사항증명서 문자 추출과 위험 키워드 분석 API를 추가했습니다.
4. 결과 화면에 PDF 업로드, 근거 페이지·문맥 표시, 분석 가능/불가능 범위와 필수 주의사항을 추가했습니다.
5. Java 전체 소스와 테스트 소스 컴파일 및 신규 JavaScript 문법 검사를 수행했습니다.

#### SMS 구현 내용

- 네이버 SENS Signature V2(HMAC-SHA256) 생성 및 `POST /sms/v2/services/{serviceId}/messages` 요청 구현
- 기본값 `SMS_PROVIDER=disabled`: 키가 없는 동안 외부 발송 없음
- `SMS_PROVIDER=naver-sens` 설정 시 실제 발송 활성화
- 전화번호별 1분에 1회, 하루 5회, 서비스 전체 하루 100회 제한
- 인증번호 5분 만료 및 입력 실패 5회 제한 유지
- 필요한 환경변수: `NCP_ACCESS_KEY`, `NCP_SECRET_KEY`, `NCP_SENS_SERVICE_ID`, `NCP_SMS_FROM`

#### PDF 분석 구현 내용

- `POST /api/defense/registry-analysis` (`multipart/form-data`, 로그인 필요)
- PDF만 허용하고 파일 헤더, 암호화 여부, 최대 10MB를 검증
- 파일을 디스크에 저장하지 않고 요청 메모리에서 분석 후 폐기
- 신탁, 압류, 가압류, 가처분, 경매, 근저당권, 전세권, 임차권등기 탐지
- 각 발견 항목에 위험 단계, PDF 페이지, 주변 원문을 함께 반환
- 문자 레이어가 없는 스캔 PDF는 분석 결과를 추측하지 않고 OCR 공급자 연결이 필요하다고 안내
- 화면에 최신 권리변동·문서 진위·숨겨진 채무·법률 판단은 확인할 수 없음을 상시 표시
- 위험 키워드가 없더라도 안전 판정을 하지 않고 원문 확인을 안내

#### 검증 결과

- `gradlew compileJava compileTestJava --no-daemon --rerun-tasks`: 성공
- `node --check static/js/registry-analysis.js`: 성공
- 기존 `build` 보고서가 다른 프로세스에 열려 있어 `clean`만 실패했으며, 소스 전체 재컴파일은 정상 완료했습니다.

#### 현재 제한

- SENS 계정·발신번호·API 키가 없어 실제 문자 발송 시험은 보류했습니다.
- 현재 PDF 분석은 문자가 포함된 PDF에 적용됩니다. 사진으로 스캔된 PDF의 이미지 OCR은 CLOVA OCR 등 공급자 연결 후 추가해야 합니다.
- AI 결과는 업로드 문서의 참고 분석이며 최신 공식 등기 조회나 법률 검토가 아닙니다.

### 2026-08-21 — 회원 보안·마이페이지·관리자 운영 기능 보강

이번 작업은 운영용 Spring Boot/MySQL 백엔드를 기준으로 진행했으며 기존 Node.js 프로토타입은 유지했습니다.

#### 작업 과정

1. 기존 회원, 문의, 매물, 방문 예약, 커뮤니티 엔티티와 API 및 관리자/마이페이지 화면의 실제 연동 상태를 점검했습니다.
2. Flyway `V2__account_security_and_admin.sql`을 추가해 로그인 잠금, 연락처 인증, 탈퇴, 게시글 소프트 삭제, 관리자 감사 로그 데이터를 저장하도록 스키마를 확장했습니다.
3. 회원 보안 서비스를 구현한 뒤 마이페이지와 관리자 화면을 서버 API에 연결했습니다.
4. Spring Cache와 Scheduler를 활성화하고 관리자 대시보드 통계를 60초 간격으로 갱신하도록 구성했습니다.
5. Java 컴파일과 테스트를 수행했습니다. 메인/테스트 소스 컴파일은 성공했지만, 현재 한글·쉼표가 포함된 Windows 프로젝트 경로에서 Gradle 테스트 워커가 생성된 `AuthApiTest.class`를 찾지 못하는 기존 실행환경 문제가 발생했습니다. 상세 내용은 아래 검증 항목에 기록했습니다.

#### 구현 내용

- 이메일/SMS 인증번호: `POST /api/auth/verification/send`, `POST /api/auth/verification/verify`
- 비밀번호 재설정: `POST /api/auth/verification/reset-password`
- 회원정보 수정: `PATCH /api/account/profile`
- 비밀번호 변경: `PATCH /api/account/password`
- 회원탈퇴: `DELETE /api/account`
- 로그인 실패 5회 시 15분 잠금 및 성공 시 실패 횟수 초기화
- 마이페이지에서 `/api/favorites`, `/api/properties/mine`, `/api/inquiries`, `/api/visits`를 병렬 조회
- 관리자 통계: `GET /api/admin/dashboard`에서 오늘 가입자, 활성 회원, 신규/미답변 문의, 검토 대기 매물, 방문 대기 건수 제공
- 통계 결과 캐시 및 기본 60초 주기 무효화
- 관리자 방문 예약 목록·상태 필터·승인·거절 화면 연결
- 문의·커뮤니티 관리자 목록의 서버 검색/페이지네이션, 매물·방문 목록의 상태 필터/페이지네이션 지원
- 커뮤니티 게시글 즉시 삭제를 소프트 삭제로 변경하고 삭제 사유와 복구 API 추가
- 매물 상태, 문의 답변, 방문 처리, 게시글 삭제/복구 시 관리자 감사 로그 저장
- 문의 답변 API는 기존 구현에 맞춰 `PATCH /api/admin/inquiries/{id}/answer` 유지

#### 운영 환경 설정

- 이메일 발송에는 `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` 설정이 필요합니다.
- SMS 발송은 네이버 SENS를 사용하며 `SMS_PROVIDER=naver-sens`와 NCP API 키·서비스 ID·등록 발신번호 설정이 필요합니다.
- 인증번호 해시 보호를 위해 운영 환경에서 `VERIFICATION_PEPPER`를 긴 임의 문자열로 반드시 교체해야 합니다.
- 통계 갱신 간격은 `ADMIN_STATISTICS_REFRESH_MS`로 조절하며 기본값은 60,000ms입니다.

#### 검증 결과

- `gradlew clean test`: `compileJava`, `compileTestJava` 성공
- 테스트 실행: Windows의 현재 프로젝트 경로 문자 처리 문제로 Gradle 테스트 워커에서 `ClassNotFoundException: com.zipai.AuthApiTest` 발생. 생성된 클래스 파일은 `build/classes/java/test/com/zipai/AuthApiTest.class`에 존재함을 확인했습니다. 영문 단순 경로에서 재실행이 필요합니다.

## 1. 프로젝트명

- **프로젝트명:** ZipAI (집아이) - AI 기반 청년 주거 안전 플랫폼
- **Demo URL:** https://zipai2026.netlify.app/
- **시연 방법:**
  1. 배포된 데모 URL(https://zipai2026.netlify.app/)에 접속합니다.
  2. 메인 화면(index.html)에서 지도 기반 매물(일반 전·월세 및 LH·공공임대)을 탐색하고 필터링해 봅니다.
  3. 사기방지 메뉴에서 계약 안전성 체크리스트를 수행하고, 전세가율 계산기를 이용해 위험도를 진단한 뒤 최종 종합 진단 리포트를 확인합니다.
  4. 행복주택 메뉴에서 자격 요건(나이, 소득, 자산 등)을 입력하여 신청자격 간편진단을 수행합니다.
  5. 고객센터에서 FAQ 검색 및 1:1 문의를 등록하고, 관리자 페이지(`templates/admin/admin.html`)에서 접수된 문의 답변 등록 및 상태 관리를 시연합니다.
     *(주의: Render 무료 플랜을 사용하므로, 최초 접속 시 백엔드 서버의 Cold Start로 인해 로그인, 찜, 문의 등록 등 서버 API 기능 동작에 약 1분의 지연이 발생할 수 있습니다. 이 경우 잠시 기다린 후 새로고침하여 시연해 주시기 바랍니다.)*
- **로그인 방법:**
  - **일반 사용자:** 로그인 페이지(`templates/member/login.html`)에서 회원가입(`signup.html`)을 진행한 후, 생성한 계정으로 로그인하여 마이페이지, 찜하기, 매물 등록 및 1:1 문의 기능을 시연해 볼 수 있습니다.
  - **관리자:** 관리자 기능(`admin.html`)을 테스트하려면 `admin` 계정으로 로그인해야 합니다. 회원가입 시 아이디를 `admin`으로 가입하거나, 서버 데이터베이스에 등록된 관리자 계정으로 로그인하여 사용할 수 있습니다.

- **안전 정보 지도 통합**: 매물 탐색 지도에 치안 시설(CCTV, 비상벨, 경찰서) 및 위험 주의 구간 정보 등을 시각적으로 결합하여 제공합니다.
- **자가 진단 기반 사기 예방**: 전세사기 유형별 체크리스트와 간편한 전세가율 계산 도구를 제공해 계약 위험을 예방합니다.

- **일관되고 편리한 사용자 경험(UX)**: 로그인, 상세 매물 탐색, 계약 자가진단, 고객센터로 이어지는 자연스러운 동선을 구축합니다.
- **반응형 최적화**: PC, 태블릿, 모바일 등 다양한 기기에 유연하게 대응하는 반응형 레이아웃을 제공합니다.

## 4. 기획 의도

청년층 및 사회초년생이 주거지를 선택할 때 비용 외에도 치안과 안전 여부가 매우 중요한 결정 요인입니다. 그러나 기존 부동산 플랫폼은 매물의 가격과 구조 중심의 거래 정보만 강조하여, 안전 정보나 전세사기 가능성을 판단하기 위해서는 공공 및 지자체 사이트를 따로 찾아야 하는 번거로움이 있었습니다.

집아이는 **"데이터로 찾고, 안전하게 계약하는 플랫폼"**이라는 철학 하에, 지도상에서 실시간으로 안전 인프라를 분석하고, 계약 전 5분 자가진단을 거쳐, 대상별 정부 맞춤형 금융지원정책을 연동하는 올인원 주거 안심 서비스를 지향합니다.

## 5. 기술 스택

- **기본 웹 기술**: HTML5, CSS3, JavaScript (ES6+ Vanilla JS)
- **지도 연동 API**: 네이버 지도 API (Naver Map API v3 SDK)

## 2026-08-24 로컬 시연용 복사본 실행 환경 구성

이 폴더만 독립적으로 실행하고 원본 프로젝트의 GitHub, Netlify, Render 및 운영 데이터에 영향을 주지 않도록 로컬 시연 환경을 구성했습니다.

### 적용 내용

- 이 복사본의 Git 원격 저장소 `origin`을 제거했습니다. 따라서 이 폴더에서는 원본 GitHub 저장소로 바로 push할 수 없습니다.
- `local-demo` Spring 프로필과 파일형 H2 데이터베이스를 추가했습니다.
- 로컬 데이터는 `data/zipai-local.mv.db`에만 저장되며 운영 MySQL/Render 데이터베이스를 사용하지 않습니다.
- H2 데이터 파일은 `.gitignore`에 등록했습니다.
- 시연용 일반 회원과 관리자 계정을 최초 실행 시 자동 생성하도록 구성했습니다.
- 문자 발송 공급자는 로컬 시연 환경에서 비활성화했습니다. SMS 연동용 코드는 유지되지만 실제 문자는 발송되지 않습니다.
- 한글과 문장부호가 포함된 Windows 복사 경로에서도 빌드되도록 Gradle 증분 컴파일을 비활성화했습니다.

### 실행 방법

프로젝트 루트의 PowerShell에서 다음 명령을 실행합니다.

```powershell
.\gradlew.bat bootRun --no-daemon --args="--spring.profiles.active=local-demo"
```

서버가 시작되면 브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:4173/index.html
```

Live Server만 실행하면 정적 화면 일부만 열리며 백엔드 API가 필요한 로그인, 관리자 기능, 데이터 저장 기능은 동작하지 않습니다. 위 명령으로 Spring Boot 서버를 실행해야 전체 기능을 확인할 수 있습니다.

## 2026-08-27 게시판 재진입 시 작성 글 미표시 수정

## 2026-08-27 전체 기능 500 오류 점검 및 보강

- 방문 예약 상세 500 오류를 수정했습니다. 과거 예약의 사용자 연관 객체를 직접 역참조하지 않고 `예약 ID + 로그인 사용자 ID`를 DB 조회 조건으로 검증하도록 변경했습니다. 같은 방식을 취소와 일정 변경에도 적용했습니다.

## 2026-09-04 자체·카카오·구글 회원가입/로그인 구현

- 기존 ZipAI 아이디·비밀번호 회원가입과 로그인을 유지했습니다.
- 로그인 및 회원가입 화면에 `카카오로 계속하기/회원가입`, `Google로 계속하기/회원가입` 버튼을 추가했습니다.
- `GET /api/auth/oauth/{provider}/start`에서 공급자 인가 화면으로 이동하고, `GET /api/auth/oauth/{provider}/callback`에서 인가 코드 교환·사용자 정보 확인·ZipAI 세션 생성을 처리합니다.
- OAuth 요청마다 무작위 `state`를 세션에 저장하고 콜백에서 공급자와 함께 검증하여 로그인 CSRF를 방지합니다.
- 신규 소셜 사용자는 최초 로그인 시 자동 가입됩니다. 공급자가 검증한 이메일이 기존 ZipAI 계정과 같으면 해당 계정에 소셜 ID를 연결합니다.
- 한 사용자가 카카오·구글을 모두 연결할 수 있도록 `oauth_identities` 테이블을 별도로 추가했습니다. 공급자 액세스 토큰은 DB에 저장하지 않습니다.
- 카카오 이메일 제공에 동의하지 않은 경우에도 공급자 고유 ID 기반 내부 이메일로 계정을 생성할 수 있습니다.
- OAuth 키가 없으면 화면 버튼을 비활성화하고 시작 API는 HTTP 503 설정 안내를 반환합니다. 기존 자체 로그인은 계속 정상 동작합니다.
- 운영 DB 마이그레이션은 `V6__oauth_identities.sql`, 로컬 H2는 `local-demo-schema.sql`에 반영했습니다.

### OAuth 환경 변수와 콜백 주소

```text
PUBLIC_BASE_URL=http://127.0.0.1:4173
KAKAO_CLIENT_ID=카카오_REST_API_키
KAKAO_CLIENT_SECRET=카카오_클라이언트_시크릿
GOOGLE_CLIENT_ID=구글_클라이언트_ID
GOOGLE_CLIENT_SECRET=구글_클라이언트_보안비밀
```

개발자 콘솔에 아래 주소를 정확히 등록해야 합니다.

- 카카오: `http://127.0.0.1:4173/api/auth/oauth/kakao/callback`
- 구글: `http://127.0.0.1:4173/api/auth/oauth/google/callback`

운영 배포에서는 `PUBLIC_BASE_URL`을 실제 HTTPS 도메인으로 변경하고 같은 도메인의 콜백 주소를 카카오·구글 개발자 콘솔에 등록해야 합니다.

검증 결과 Java 컴파일·리소스 빌드와 로그인/회원가입 JavaScript 문법 검사가 성공했습니다. 키 없음 상태의 공급자 상태 API 200·시작 API 503, 기존 자체 로그인 200을 확인했습니다. 시험용 키 상태에서는 카카오·구글 인가 URL이 HTTP 302로 생성되고 콜백 주소와 무작위 `state`가 포함되는 것을 확인했습니다. 실제 공급자 로그인 완료는 발급받은 운영/테스트 키 등록 후 확인할 수 있습니다.
